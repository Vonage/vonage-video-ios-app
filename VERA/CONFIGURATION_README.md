# VERA Dynamic Configuration System

This system allows enabling or disabling VERA application features through JSON configuration.

## Important Files

- `./Config/app-config.json`: Main configuration file
- `Scripts/generate-app-config.py`: Generates Swift code from JSON configuration
- `VERAConfiguration/VERAConfiguration/AppConfig.swift`: Auto-generated code (committed; do not edit manually)

## How It Works

Configuration gates features through two mechanisms:

1. **Runtime gating (meeting-room features)** — chat, captions, reactions, screen share, and the other in-call features are always compiled (linked via `VERAMeetingRoomSDK`) and enabled at runtime. `DependencyContainer.meetingRoomEnabledFeatures` (in `VERAApp`) maps `AppConfig` keys to `MeetingRoomFeature` cases, and `MeetingRoomSDKContainer` gates plugin registration and UI on `enabledFeatures.contains(_:)`.
2. **Compile-time flags (app-level features)** — `Project.swift` reads `app-config.json` at `tuist generate` time, adds the corresponding module targets as app dependencies, and sets Swift compilation conditions on the VERA app target: `ARCHIVING_ENABLED`, `BACKGROUND_EFFECTS_ENABLED`, `SETTINGS_ENABLED`, `AUDIOEFFECTS_ENABLED`, `AUDIODIAGNOSTICS_ENABLED`, `FEEDBACK_ENABLED`.

## Example: Enable/Disable Chat

In `app-config.json`:

```json
{
  "meetingRoomSettings": {
    "allowChat": true  // change to false to disable
  }
}
```

Then regenerate:

```bash
python3 Scripts/generate-app-config.py
tuist generate
```

When `allowChat` is `false`, `.chat` is left out of `meetingRoomEnabledFeatures`, so the chat plugin is never registered and the chat button does not appear. The chat module is still linked (runtime gating), so build size does not change — unlike compile-flagged features such as archiving, whose modules drop out of the app entirely.

## Adding New Configurations

To add a new configurable feature:

1. Add the key to `app-config.json`
2. Update `Scripts/generate-app-config.py` to read the new key — the generator is a hardcoded template, so add the struct property, the defaulted `init` parameter, and the assignment; then run it and commit the regenerated `AppConfig.swift`
3. For a meeting-room feature: add a `MeetingRoomFeature` case, map it in `DependencyContainer.meetingRoomEnabledFeatures`, and gate behavior in `MeetingRoomSDKContainer` with `enabledFeatures.contains(_:)`
4. For an app-level feature: add a reader function in `Project.swift`, wire it into `createDependencies()` / `createBuildSettings()`, and use `#if FEATURE_ENABLED` in `VERAApp` code
5. Gate the module's test targets in `Tuist/ProjectDescriptionHelpers/TestSchemes.swift`

## Accessing Configuration in Code

The generated configuration is available as static properties:

```swift
let chatEnabled = AppConfig.meetingRoomSettings.allowChat
let videoOnJoin = AppConfig.videoSettings.allowVideoOnJoin
let defaultLayout = AppConfig.meetingRoomSettings.defaultLayoutMode
```

For testability, view models take `AppConfig` via dependency injection; all nested struct properties have default values matching the JSON, so tests can override individual values: `AppConfig(videoSettings: .init(allowCameraControl: false))`.

## Troubleshooting

### Verify Generation Works
```bash
python3 Scripts/generate-app-config.py
```

### If `tuist generate` fails
1. Verify that `app-config.json` is valid JSON
2. Test the generation script manually: `python3 Scripts/generate-app-config.py`
3. Verify that `VERAConfiguration/VERAConfiguration/AppConfig.swift` was regenerated
4. A `fatalError` mentioning a missing config key usually means a key referenced by `Project.swift` or `TestSchemes.swift` was renamed or removed from the JSON

### Build Settings Not Applied (app-level flags)
1. Check that the flag (e.g. `ARCHIVING_ENABLED`) appears in the VERA app target's **Swift Compiler - Custom Flags** → **Active Compilation Conditions** — the flags apply to the app target only, never to module frameworks
2. Verify the script output shows the feature as enabled during `tuist generate`
3. Clean and regenerate: `tuist clean && tuist generate`

## Important Notes

- `AppConfig.swift` is generated by `generate-app-config.py`, not on each build — rerun the script after editing the JSON and commit the result (CI does not run it)
- Always run `tuist generate` after changing `app-config.json`
- New JSON keys do **not** flow through to `AppConfig.swift` automatically; the generator must be updated by hand
